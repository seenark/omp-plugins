# CodeGraph, Beads, and OMP integration research

**Research snapshot:** 2026-10-02. This note records primary-source findings, local observations, and interview decisions separately. Installed OMP is [18.3.1](../../node_modules/@oh-my-pi/pi-coding-agent/package.json#L1-L3). Upstream links describe the documentation/source consulted; unpinned `main` and published documentation can change. This is not an ADR or implementation specification.

## Findings

- **Installation, initialized project data, and runtime use are independent layers.** CodeGraph's `install` configures agents; `init` builds project data. Beads needs an available `bd` executable and an initialized workspace; agent guidance, hooks, and MCP are separate integration concerns. In this repository, OMP plugin enablement is a next-start lifecycle fact, not a live project toggle ([CodeGraph quickstart](https://colbymchenry.github.io/codegraph/getting-started/quickstart/), [Beads init](https://beads.gascity.com/cli-reference/init), [Beads MCP](https://beads.gascity.com/integrations/mcp-server), [ADR 0004, L6-L14](../adr/0004-package-config-command-cutover.md#L6-L14)). A directory alone therefore does not establish operational readiness.

- **CodeGraph detects initialized database state, not merely `.codegraph/`.** Default storage is `<project>/.codegraph/codegraph.db`; init checks SQLite and CodeGraph schema. `CODEGRAPH_DIR` and WSL handling can change the directory. Project resolution walks upward to the nearest initialized root. `init` creates the initial index; `index` rebuilds it; `sync` updates changes; `status` reports initialization/statistics. The schema contains `schema_versions` and `project_metadata`, but that does not establish a compatibility guarantee ([directory source](https://github.com/colbymchenry/codegraph/blob/main/src/directory.ts), [CLI source](https://github.com/colbymchenry/codegraph/blob/main/src/bin/codegraph.ts), [schema](https://github.com/colbymchenry/codegraph/blob/main/src/db/schema.sql), [indexing guide](https://colbymchenry.github.io/codegraph/guides/indexing/)). CLI `explore` and MCP `codegraph_explore` have output parity in the installed help observed below; this does not mean both transports are configured or callable. MCP accepts `projectPath` to select an indexed project ([upstream README](https://github.com/colbymchenry/codegraph/blob/main/README.md)).

- **Beads discovery must respect workspace resolution.** Discovery walks upward; `BEADS_DIR`, redirects, and worktree sharing can select a workspace other than `cwd/.beads`. `bd where --json` reports the resolved workspace; `bd context --json` reports effective context; `bd doctor --json` checks health. `bd ready --json` lists unblocked work, not generic readiness. Current upstream uses Dolt, not the removed SQLite backend ([where](https://beads.gascity.com/cli-reference/where), [context](https://beads.gascity.com/cli-reference/context), [doctor](https://beads.gascity.com/cli-reference/doctor), [ready](https://beads.gascity.com/cli-reference/ready), [upstream README](https://github.com/gastownhall/beads/blob/main/README.md)).

- **Beads initialization has integration side effects.** `bd init` creates `.beads/` and database state, normally generates agent guidance including `AGENTS.md`, and installs hooks/integrations unless skipped. `--skip-agents` is required when initialization must avoid generated agent files; hook consent is separate and uses `--skip-hooks`. `--quiet`/`--non-interactive` are not side-effect opt-outs. `--init-if-missing` skips an existing workspace; ordinary repeated init is not an unconditional successful no-op. Role, stealth mode, server mode, and Git remote/history behavior also affect initialization ([init flags](https://beads.gascity.com/cli-reference/init), [init safety](https://beads.gascity.com/cli-reference/init-safety), [IDE setup](https://beads.gascity.com/getting-started/ide-setup)). CodeGraph's instruction-writing belongs to `install`, not project `init` ([installation](https://colbymchenry.github.io/codegraph/getting-started/installation/)).

## OMP-native building blocks and existing ownership

- **Project context and runtime instructions:** `ExtensionContext.cwd` exposes the current directory; `mode` and `hasUI` distinguish interactive capability. `ctx.getSystemPrompt()` returns `string[]`; `before_agent_start` can return a replacement `systemPrompt: string[]`, with extensions chaining in order ([context, L266-L280](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/extensions/types.d.ts#L266-L280), [prompt getter, L307-L308](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/extensions/types.d.ts#L307-L308), [result, L805-L808](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/extensions/types.d.ts#L805-L808), [event, L862](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/extensions/types.d.ts#L862)). **Runtime instructions can avoid plugin edits to `AGENTS.md`, but apply only in OMP with the extension loaded.** They do not configure other agents or give teammates instructions. Beads init still needs `--skip-agents` to avoid its own agent-file generation; runtime injection does not suppress upstream side effects.

- **Tools and status:** `registerTool()` exposes an LLM-callable tool; `getActiveTools()`, `getAllTools()`, and `setActiveTools()` provide runtime tool control. Listing a tool is not proof that its external dependency works. Native `ctx.ui.setStatus(key, text)` is available independently of Shared Display ([registration, L893-L894](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/extensions/types.d.ts#L893-L894), [tool control, L1005-L1010](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/extensions/types.d.ts#L1005-L1010), [status, L139-L140](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/extensions/types.d.ts#L139-L140)).

- **MCP readiness has a public-interface limit.** Tool metadata and active names identify configured, enabled tools; the installed ExtensionAPI exposes no direct invocation or connection-health query for an existing MCP tool. Tool-result events reveal outcomes only after calls. Neither metadata nor a past successful call guarantees current server health ([metadata, L499-L506](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/extensions/types.d.ts#L499-L506), [tool methods, L1005-L1010](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/extensions/types.d.ts#L1005-L1010), [result events, L704-L778](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/extensions/types.d.ts#L704-L778)).

- **Exclusive Shared Display fallback needs host-presence evidence.** The existing producer contract has `publish` and `dispose`, and its request/snapshot protocol has no retained host-presence or visibility signal. Caveman currently updates native status separately from publishing. The selected “Shared Display, otherwise footer” behavior must not infer that a host is active merely because an EventBus exists ([client contract, L11-L19](../../packages/shared-display/src/client.ts#L11-L19), [producer handshake, L165-L217](../../packages/shared-display/src/client.ts#L165-L217), [Caveman status, L213-L239](../../packages/caveman/src/index.ts#L213-L239)).

- **Configuration capability is not configuration ownership.** OMP manifests support typed settings; native project overrides support disabled plugins, feature overrides, and settings in `.omp/plugin-overrides.json` ([schemas, L39-L74](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/plugins/types.d.ts#L39-L74), [overrides, L117-L127](../../node_modules/@oh-my-pi/pi-coding-agent/dist/types/extensibility/plugins/types.d.ts#L117-L127)). Codesook already owns `/codesook-omp-plugin` and `~/.config/codesook-omp/config.json`, with separate `display` and `behavior` groups, staged Apply/Cancel, atomic persistence, and live configuration events. This existing root contract must not be mistaken for a settled project-policy storage contract ([ADR 0004, L6-L14](../adr/0004-package-config-command-cutover.md#L6-L14), [vocabulary, L125-L139](../../CONTEXT.md#L125-L139)).

## Interview status

**User decisions recorded:**

- CodeGraph and Beads remain separate plugins. CodeGraph uses the user's OMP-configured MCP tools; Beads uses its CLI.
- Existing project data initialized outside OMP is detected too. Data directories alone do not establish readiness.
- Instructions use the runtime system prompt only. These plugins do not write AGENTS.md or remove instructions already present there.
- Shared project settings select automatic integration guidance or suppression independently for each tool. Suppression does not hide MCP tools, block CLI access, disconnect servers, or delete data.
- A repository working tree owns project policy and new initialization; outside Git, the active directory is the project. Existing external-tool workspaces follow their tools' discovery/redirection rules.
- Initialization preserves project policy: an off project remains off after init.
- Beads issue operations require an explicit user request. Initialization offers standard/team or stealth mode and an opt-in Git-hook choice, with hooks off by default. It always skips agent-file generation and does not set up other agents.
- Status visibility is configurable, with ready-only as the default. CodeGraph readiness means usable project data plus an enabled MCP tool, not verified connection health; detailed status must state that limit.
- Status uses Shared Display when its host is active, otherwise the native OMP footer.
- Refresh runs at session startup, before a user turn, or through plugin commands. No idle polling or background watcher.

**Confirmation status:** the user confirmed the consolidated design and chose documentation only, without starting implementation. The confirmed command surface, shared project override location, runtime rules, status behavior, and acceptance criteria are recorded in [CodeGraph and Beads Plugin Design](../codegraph-beads-plugins.md). No plugin implementation has been changed.
